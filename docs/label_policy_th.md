# BirdNests Label Policy

เวอร์ชันนโยบาย: `v0.1-pretraining`
วันที่จัดทำ: 2026-06-24
สถานะ: ใช้สำหรับเตรียมข้อมูลก่อนเทรนโมเดล ห้ามถือเป็นผลลัพธ์ production

## 1. วัตถุประสงค์ของ Label

ระบบต้องรองรับผลลัพธ์ต่อไปนี้ในระยะถัดไป:

- วงตำแหน่งจุดสกปรก
- นับจำนวนจุดสกปรก
- ให้คะแนนความสะอาดของภาพ
- ตัดสินสถานะ `ผ่าน`, `ไม่ผ่าน`, หรือ `ต้องตรวจซ้ำ`
- ส่งออกผลเป็น CSV และแสดงใน Control Panel

`anomaly_detection.py` ใน workflow ปัจจุบันเป็นเครื่องมือจัดอันดับภาพ/patch ที่น่าสงสัยเพื่อให้คนตรวจ ไม่ใช่โมเดล clean/dirty ขั้นสุดท้าย

## 2. นิยาม Class

### `clean`

ภาพหรือ crop ที่ไม่มีจุดสกปรกตามนิยามในเอกสารนี้ และภาพมีคุณภาพเพียงพอสำหรับตรวจด้วยตา/ระบบ

### `dirty`

ภาพหรือ crop ที่พบจุดสกปรกอย่างน้อย 1 จุดตามนิยามในเอกสารนี้

### `uncertain`

ภาพที่ระบบหรือผู้ตรวจยังไม่มั่นใจ เช่น จุดเล็กเกินเกณฑ์, มี artifact จากแสง/เงา, หรือผู้ตรวจสองคนให้ความเห็นไม่ตรงกันและยังไม่มีคำตัดสินสุดท้าย

### `unreviewable`

ภาพที่ตรวจไม่ได้ เช่น เบลอมาก, มืดมาก, สว่างจ้าเกินไป, crop ผิดตำแหน่ง, ภาพเสียหาย, หรือมองรายละเอียดรังนกไม่ชัดพอ ต้องแยกออกจากชุด train/evaluate หลัก และส่งเข้าคิว `ต้องตรวจซ้ำ`

## 3. นิยามจุดสกปรก

จุดสกปรกหมายถึงบริเวณผิดปกติบนรังนก เช่น:

- คราบดำ
- เศษฝุ่น
- รอยเสียหาย
- จุดสีผิดปกติ
- สิ่งผิดปกติอื่นที่ผู้ตรวจยืนยันว่าไม่ใช่ลักษณะปกติของรังนก

Blue marker ในภาพ marked (`*m.jpg`) ให้ถือเป็นตำแหน่งจุดสกปรกเบื้องต้นตาม policy ผู้ใช้ โดย `1 marker = 1 จุดสกปรก` และ marker ระบุโดยผู้ตรวจ/ผู้เชี่ยวชาญแล้ว อย่างไรก็ตาม ก่อนใช้เป็น ground truth สุดท้ายสำหรับ metrics ต้องมีการ review และบันทึกใน ground-truth manifest

## 4. ขนาดขั้นต่ำและกฎการนับ

- ขนาดขั้นต่ำของจุดสกปรก: `TBD — ต้องกำหนดก่อนเทรนโมเดล` โดยระยะเตรียมข้อมูลนี้ให้เรียนรู้เบื้องต้นจาก `dirty_positive` และ `dirty_spot_id` ในผล crop/backtest
- จุดหรือคราบที่ติดกันเป็นก้อนใหญ่ ให้นับเป็น `1 จุด`
- จุดที่อยู่บริเวณขอบภาพหรือขอบ crop ให้นับเป็นจุดสกปรกได้ ถ้าผู้ตรวจเห็นว่าเป็นตำแหน่งจริงบนรังนก ไม่ใช่ artifact จากการ crop
- ถ้าจุดเดียวถูกแบ่งไปหลาย crop ต้องเก็บ `source_image` และ `spot_id` เพื่อป้องกันการนับซ้ำในระดับภาพ

## 5. คุณภาพภาพที่ตรวจไม่ได้

ภาพเบลอ มืด หรือมองไม่ชัด ให้จัดเป็น `unreviewable` และแสดงสถานะ `ต้องตรวจซ้ำ` ไม่ควรนำไป train เป็น `clean` หรือ `dirty` โดยตรงจนกว่าจะมีคำตัดสินจากผู้ตรวจ

## 6. สถานะ Blue Marker

สำหรับระยะนี้ Blue marker มีสถานะเป็น `preliminary label` ที่เชื่อถือได้พอสำหรับสร้าง manifest และ review queue

ก่อน train/evaluate โมเดลสุดท้าย ต้องยืนยันอย่างน้อย:

- ภาพ original และ marked ตรงคู่กัน
- ขนาดภาพตรงกัน
- marker ไม่เลื่อนตำแหน่งเกินระดับที่ยอมรับได้
- ผู้ตรวจยืนยันจำนวนจุดและ class ระดับภาพแล้ว

ใน audit ล่าสุดพบ source image pairs 15 คู่ และทุกคู่มี dimensions ตรงกัน แต่ยังต้องบันทึกผล review สุดท้ายใน manifest

## 7. Mapping จำนวนจุดเป็นคะแนนความสะอาด

| จำนวนจุดสกปรกที่ตรวจพบ | คะแนนความสะอาด |
| --- | ---: |
| 0-9 จุด | 95% |
| 10-20 จุด | 90% |
| 21-30 จุด | 80% |
| 31 จุดขึ้นไป | 70% |

เปอร์เซ็นต์นี้หมายถึงคุณภาพ/ความสะอาดของรังนกในภาพ ไม่ใช่ confidence ของโมเดล

## 8. Pass / Fail / Review

- `ผ่าน`: คะแนนความสะอาดตั้งแต่ 80% ขึ้นไป
- `ไม่ผ่าน`: คะแนนต่ำกว่า 70%
- `ต้องตรวจซ้ำ`: ภาพเบลอ มืด มองไม่ชัด หรือโมเดลไม่มั่นใจ

หมายเหตุ: จาก mapping ปัจจุบันคะแนนต่ำสุดคือ 70% จึงยังไม่มีช่วงที่ต่ำกว่า 70% จากจำนวนจุดเพียงอย่างเดียว ถ้าธุรกิจต้องการ class `ไม่ผ่าน` จากจำนวนจุด ต้องกำหนดเพิ่มว่า `31 จุดขึ้นไป = ไม่ผ่าน` หรือเพิ่มระดับคะแนนต่ำกว่า 70%

## 9. False Reject และ False Accept

- False Reject: ของดีแต่ระบบบอกเสีย หรือภาพที่ควร `ผ่าน` แต่ระบบทำนายเป็น `ไม่ผ่าน`/reject
- False Accept: ของเสียแต่ระบบบอกผ่าน หรือภาพที่ควร `ไม่ผ่าน` แต่ระบบทำนายเป็น `ผ่าน`

ความเสี่ยงหลักคือ False Accept เพราะรังนกเป็นผลิตภัณฑ์สำหรับรับประทาน จึงต้องให้ priority สูงสุดกับการลด False Accept

## 10. เป้าหมาย KPI

| ตัวชี้วัด | เป้าหมาย |
| --- | ---: |
| Accuracy | ไม่น้อยกว่า 92% |
| Precision ของ class ไม่ผ่าน/สกปรก | ไม่น้อยกว่า 90% |
| Recall ของ class ไม่ผ่าน/สกปรก | ไม่น้อยกว่า 95% |
| F1-score | ไม่น้อยกว่า 92% |
| False Reject | ไม่เกิน 5% |
| False Accept | ไม่เกิน 1% |
| เวลาประมวลผลต่อภาพ | ไม่เกิน 5 วินาที |
| ภาพที่ส่งให้คนตรวจซ้ำ | ไม่เกิน 8% |

ยังห้ามอ้างค่าจริงของ KPI เหล่านี้จนกว่าจะมี ground truth ครบและมีโมเดลที่ evaluate บน test set แยกตาม source image

## 11. Workflow ผู้ตรวจ

1. ใช้ Blue marker และผลจาก `dirty_positive` เป็น preliminary label
2. ผู้ตรวจหลักและหัวหน้าตรวจทานจำนวนจุด, class ภาพ, และสถานะ pass/fail/review
3. ถ้าผู้ตรวจเห็นต่าง ให้ใช้การตัดสินใจร่วมกันและบันทึกผลสุดท้ายลง manifest
4. ภาพที่ไม่ชัดหรือระบบไม่มั่นใจให้ส่งเข้า review queue
5. ห้ามนำภาพที่ยัง `uncertain` หรือ `unreviewable` ไปวัดผล final metrics

## 12. รายการที่ยังต้องกำหนดก่อนเทรนโมเดล

- ขนาดขั้นต่ำเชิง pixel หรือพื้นที่จริงที่นับเป็น 1 จุดสกปรก
- ระยะห่างสูงสุดที่ยังถือว่าจุดติดกันเป็นก้อนเดียว
- นิยาม `ไม่ผ่าน` เมื่อ mapping ปัจจุบันให้คะแนนต่ำสุด 70% แต่เกณฑ์ fail ระบุว่าต่ำกว่า 70%
- รูปแบบ label ตำแหน่งสุดท้ายที่ต้องการ: circle center, bounding box, mask, หรือทั้งหมด
- เกณฑ์ยอมรับตำแหน่ง detection เช่น IoU, center-distance tolerance, หรือ point matching radius
