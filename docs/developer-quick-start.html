Developer Quick Start

A compact path for setting up the BirdNests Faster R-CNN Prototype, finding the supported runtime contract, and validating the public documentation without changing the frozen engineering scope.

Start Here

  1. Review the handoff package. Read handoff/prototype_v1/README_HANDOFF.md, then follow the installation and inference contract documents in the same folder.
  2. Create an isolated Python environment. Keep local data, checkpoints, caches, and temporary inference outputs outside Git-tracked publication paths.
  3. Install the runtime requirements for the target machine. Use the common model requirements first, then choose the CUDA package set only when the machine supports it.
  4. Run validation before changing behavior. The included unit tests validate CLI argument handling, schema construction, and public Contact Sheet links without loading the model checkpoint.

Local Setup

From the repository root, create or activate a virtual environment before installing project packages.

python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r InstallKit\requirements-core.txt
python -m pip install -r InstallKit\requirements-model-common.txt

CUDA installs must follow the official PyTorch selector for the exact target hardware. Do not assume CUDA wheels can be installed from the default PyPI index.

Supported Inference Entry Point

The supported wrapper is tools/run_prototype_inference.py. It validates arguments before loading PyTorch or the checkpoint.

python .\tools\run_prototype_inference.py `
  --input .\path\to\image-or-directory `
  --output .\prototype_inference_output `
  --checkpoint .\path\to\final_checkpoint.pt `
  --config .\handoff\prototype_v1\prototype_runtime_config.json `
  --threshold 0.125 `
  --device cpu `
  --save-json predictions.json `
  --save-preview previews
Checkpoint policy: do not commit checkpoint files to regular Git and do not copy them into docs/. Use the project Release artifact for the frozen checkpoint.

Validation

Run the focused non-inference tests when making handoff, CLI, schema, or public documentation changes.

python -m unittest tests.test_run_prototype_inference tests.test_contact_sheet_public_manifest -v

These tests do not run inference, load the checkpoint, or require CUDA.

Engineering Boundaries

  • This is an engineering Prototype, not a production-ready detector.
  • Contact Sheet labels are model-vs-marker review states, not expert decisions.
  • Do not describe all 240 approved pairs as training images.
  • Raw images, marker images, local datasets, caches, checkpoints, optimizer states, and secrets must stay out of public documentation paths unless explicitly approved.
